## Ordered writes and recovery state

The writer stages each pending migration separately. The exact coverage migration begins a transaction and sets `SET LOCAL statement_timeout = '240s'` before DDL. The recovery gate checks this source control before creating the reviewed evidence and again before applying the migration. The timeout is scoped to that transaction; it changes neither the temporary login role nor database defaults. The coverage writer credential has a 300-second TTL; the gate reserves 10 seconds for launch overhead and caps the CLI process at 240 seconds. It persists `started_unverified` before applying only the coverage migration, and successful CLI exit is recorded only as `write_command_succeeded_readback_pending`. The workflow then acquires a separate bounded credential for read-only reconciliation. Read-back requires at least 250 seconds remaining, caps each of its four SQL checks at 20 seconds and its exact dry-run at 120 seconds, and reserves 50 seconds for overhead. That phase requires the ledger prefix to advance from nine to ten, the final link migration to remain the sole pending item, source statements to match, the coverage catalog objects to exist, and the coverage-only dry-run to be empty. Only a successful read-back marks coverage `verified` and allows acquisition of a new credential for the final link migration. Any writer or read-back failure leaves coverage unverified and blocks later phases; the migration is never automatically replayed.

The final migration can start only when the local state says coverage is verified. It must then verify the exact eleven-migration release prefix, an empty pending plan, complete source/ledger agreement and the candidate-complete gate. A failure or read-back mismatch leaves the phase `started_unverified`, emits a recovery marker, exits nonzero, and uses GitHub's default step-success dependency so later writes do not run. If a writer or read-back fails, do not replay coverage. Dispatch a new protected recovery only when its read-only preflight proves the exact prefix-ten state with matching coverage ledger statements, catalog objects, and the final migration as the sole dry-run item. That run skips the coverage writer and performs read-back before it can reach the final migration. Any other state fails closed for manual investigation.
