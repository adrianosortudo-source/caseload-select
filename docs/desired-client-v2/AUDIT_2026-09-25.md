# Desired Client pre-user-test audit, 25 September 2026

Status: the scoped pre-user-test audit and regression fixes are complete. This is a prototype audit, not a production release or a lawyer usability study.

## Findings corrected

| Finding | Correction |
|---|---|
| Gemini rejected the response schema before generation | Removed repeated large source-path enums from the provider schema; retained strict server source validation and bounded arrays. |
| Real generation repeatedly exceeded the 12-second deadline | Added a 512-token reasoning budget. The final five real requests completed in 5.475 to 6.900 seconds without changing either deadline. |
| The model received commercial IDs without their actual meaning | Added canonical question/answer labels, exact ranges and unknown status to the prompt. |
| Answering an AI follow-up temporarily emptied the screen | Follow-ups and retries now show review/loading status with the structured alternative available. |
| The final allowed attempt could ask another question and discard the useful result | Server eligibility is empty for attempt index 2. |
| An unanswered clarification disappeared after resuming | Validated optional metadata now survives saving, loading, screen rendering and exports. |
| Review omitted optional commercial, delivery and direction answers | Supplied service-area, contact, commercial, delivery and direction details appear in six editable groups, with separate label/value rows. |
| First-contact choice disappeared from the result | A factual note preserves it in screen, copy, Markdown and print, separately from client identity. |
| Two selected goals ran together in one phrase | Each goal has its own statement and review row, using the full canonical wording without a repeated client-goal preface. |
| An unspecified work choice produced an unusable marketing topic | The result now tells the user to choose a specific work type first. |
| Selection limits appeared only after an extra click was rejected | Goals, concerns and delivery conditions show limits upfront. |
| Useful advice about resolving an unknown caused the whole AI result to be discarded | Only the validation-step suggestion may cite unknown answers; other unknown-source rules remain unchanged. |

Astra independently reviewed the final samples and found no P1 factual invention. The employer remains distinct from its contact; future family work remains a hypothesis; fees and time boundaries are preserved; unknowns are visible; and validation steps test the firm's profile rather than accept an individual matter.

Remaining P2 output quality findings are explicit: the commercial sample omitted variable payment timing; generated marketing proposals sometimes carry preference/hypothesis rather than suggestion labels; one validation step says confirm rather than neutrally check whether; and one employer inquiry is more article-like than conversational. These samples are suitable for prototype review, not proof of reliable quality for every combination. Further output-quality refinement should preserve the actual user preferences separately from generated recommendations.

## Functional and rendered verification

The first combined Chrome run passed 26 of 28 tests. Both failures were newly expanded review-copy wrapping at 375 and 320 pixels; before screenshots were retained and the review was changed to separate labels from values. All tested functional journeys, keyboard behaviour, comparison, recovery, printing, copy fallback, request bounds, stale response cancellation, and embedded message handling passed that run. An intermediate 12-test rerun passed nine checks, exposed two richer multi-goal phone wrapping cases, and had one Windows screenshot-file write failure. Goal choices were separated in the review; redundant goal prefaces were removed from the brief for clearer scanning. The final affected-surface rerun passed all eight checks: the richer review and brief at 1440, 1024, 768, 640, 375 and 320 pixels, plus both complete phone journeys. The earlier review-wrap failures and the intermediate screenshot-write failure did not recur. Final review screenshots were visually inspected as well. Reports: [initial 28-test run](review/audit-browser-initial.json), [intermediate 12-test run](review/audit-browser-intermediate.json), [final eight checks](review/audit-browser-final.json). Across these runs, all 34 distinct scenarios have passing coverage; this is not a claim that all 34 were rerun together after the final presentation change.

The first consolidated unit run passed 94 of 96 tests. Both failures were new Markdown test expectations that omitted the intentional punctuation escaping; the exported content itself was present. Corrected test expectations preserve the same literal content and deduplication requirement. The final consolidated rerun passed all 96 tests across 10 files. After the final canonical-goal presentation change, the 27 brief, export and storage tests passed again.

The full local TypeScript command completed with one inherited Next generated-route error: notification-batch/route.ts exports buildDigest. Its Git blob is identical at baseline 18b51a62 and current HEAD (abfd182394505b964fa5154dbb7261b5e44f55a7). No Desired Client type error was reported. This is not recorded as a full type-check pass; prior CI/Vercel build evidence and the generated-validator distinction remain in VERIFICATION.md.

The final browser review also confirmed the wrapper welcome screen loads, the temporary viewport override was reset, and the fictional audit draft was cleared before handover.

Scoped ESLint passed with zero errors and five existing warnings. The Impeccable detector reported no findings in the changed UI files. These checks are not a WCAG certification or a production performance benchmark.

## Environment and release limits

The local app had stopped before this audit; it was restarted and the preview restored. The preview remains at http://localhost:3300/tools/desired-client-matter.html, with its app on port 3301.

The real provider calls were adapter-level tests. Browser AI-success tests use fictional intercepted responses. No production configuration, database, quota storage, dependency, merge, deployment, or external message was changed. Five-lawyer usability testing has not been performed. PR 317 remains the app review vehicle; the unchanged website companion is PR 26.
